# NeuroLLM on iOS / Android (Capacitor)

The `ios/` and `android/` directories in this folder are real native Xcode/Android Studio
projects, generated by [Capacitor](https://capacitorjs.com/), that wrap the same React web app
in `src/`. They were scaffolded and synced in this environment (`npx cap add ios`,
`npx cap add android`, `npx cap sync`) — this environment has no Xcode.app or Android SDK
installed, so building/signing/installing on a device or simulator has to happen on your own
machine. This doc is that remaining walkthrough.

## Important: this is a wrapper, not a rebuild

Capacitor does not talk to the Vite dev server. `webDir: 'dist'` in `capacitor.config.ts` means
the native shell bundles whatever is in `frontend/dist/` at the time you last ran `npx cap sync`
— a static snapshot. Every time you change the web app and want the native app to reflect it:

```bash
npm run build:mobile   # = tsc -b && vite build && cap sync
```

## The backend URL problem

In the browser (dev server, or the production build served by FastAPI itself — see
`backend/app/main.py`), the app calls a same-origin `/api/...` and it just works. The native app
has no same-origin backend: its WebView serves the bundled `dist/` from
`capacitor://localhost` (iOS) / `https://localhost` (Android), so a relative `/api` request would
hit the phone itself, not your backend.

Fix: set `VITE_API_BASE_URL` to an absolute URL pointing at a real, network-reachable backend
before building for mobile — e.g. a `.env.production` in this directory:

```
VITE_API_BASE_URL=https://your-backend-host.example.com/api
```

For local development against your own machine's backend, use your machine's LAN IP (not
`localhost` — that resolves to the phone itself), e.g. `http://192.168.1.23:8000/api`, and make
sure `backend/.env`'s `CORS_ORIGINS` includes the native app's origin (`capacitor://localhost` for
iOS, `https://localhost` for Android) or is left permissive for local testing.

## iOS

Requires: a full Xcode install (not just Command Line Tools) and an Apple ID (free) or paid
Apple Developer account (needed for on-device installs / TestFlight).

```bash
npm run build:mobile
npm run cap:open:ios      # opens ios/App/App.xcworkspace in Xcode
```

In Xcode:
1. Select the `App` target → **Signing & Capabilities** → set your **Team** (your personal Apple
   ID works for local device installs; a paid account is required for TestFlight).
2. Plug in an iPhone (or pick a Simulator) from the device dropdown → press **Run** (▶).
3. First on-device run: on the iPhone, go to **Settings → General → VPN & Device Management** and
   trust your developer certificate.

For TestFlight: **Product → Archive**, then use the Organizer window to upload to App Store
Connect.

Camera permission (`NSCameraUsageDescription`) is already set in `ios/App/App/Info.plist` — the
fingerprint-enrollment camera capture flow (`src/pages/profile/Enroll.tsx`) uses the
`@capacitor/camera` native plugin on-device (falls back to browser `getUserMedia` when not
running inside Capacitor).

## Android

Requires: [Android Studio](https://developer.android.com/studio) (which bundles the Android SDK).

```bash
npm run build:mobile
npm run cap:open:android   # opens android/ in Android Studio
```

In Android Studio: let Gradle sync finish, then pick a device/emulator from the toolbar and press
**Run** (▶). For Play Store internal testing: **Build → Generate Signed App Bundle**.

The `CAMERA` permission is already declared in `android/app/src/main/AndroidManifest.xml`.

## Everything else

Every other page/feature (Overview, Evolution, Counterfactual, Research, Privacy) is the same
React app running unmodified inside the native WebView — no native code was needed beyond the
camera capture path above. If you change the web app after this, remember: `npm run build:mobile`
before testing on a device, every time.
